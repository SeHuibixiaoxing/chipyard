# MudnacSim × HybridMapper 协同机制文档（v1）

- 版本：v1
- 日期：2026-03-05
- 范围：`HybridMapper（编译侧） + MudnacSim（执行侧） + 脚本链路`
- 目标：解释模块组成、划分机制、pipeline 机制、buffer/SPM 管理、多模型调度，以及编译测与执行测协同约定和关键代码位置。

## 1. 总体协同架构

### 1.1 角色边界

- HybridMapper：离线生成模型层映射、图划分、pipeline 候选、调度点候选和 profiling 聚合文件。
- MudnacSim：加载 HybridMapper 产物，在给定硬件配置下执行单模型/多模型 pipeline 与 QoS 调度。
- 脚本层：组织参数网格、批量运行仿真、回填 segment cost、聚合成调度可消费的 profiling 文件。

### 1.2 数据流（编译测 -> 执行测）

1. 生成模型与每层 mapping（`layers.yaml` + `mapping/<layer>.yaml/.dump`）。
2. 生成图划分候选（`model_partition.yaml/.dump`）。
3. SA 生成 pipeline 候选：
   - 全模型：`entire_model/{acc}_{spm}_{batch}_{dram}_{noc}_{method}.yaml`
   - 调度点分段：`schedule_point/pipeline_mapping/<partition>/<seg>/*.yaml`
4. 仿真回填每个 segment 的实测 cost（`profiline.yaml`）。
5. 聚合为 `schedule_point_profiling_<method>.yaml`（含 target/cost/mapping_path）。
6. MudnacSim QoS 运行时按 target 检索 profiling，并在每个 subgraph 选择 mapping 路径执行。

### 1.3 目录协同关键点

- `tmp/MudnacSim/models -> ../HybridMapper/output/`（符号链接）。
- 因为该链接，MudnacSim 在 `models/pipeline/...` 读取到的就是 HybridMapper 产物。

## 6. pipeline buffer 机制

### 6.1 数据结构

- `PipelineBuffer`：维护 inUse/noUse 双缓冲索引、full 标记、运行中指令计数、SPM 页集合。
- `RingBuffer`：维护 `head/tail/use_count/out_degree`。
- 代码：`tmp/MudnacSim/src/runtime/pipeline_buffer.h:48`

### 6.2 TensorStayType 到行为映射

- `DRAM`：入口 fetch 自 DRAM，出口 flush 到 DRAM。
- `DRAM_DEPEN`：同 DRAM，但依赖 ring buffer 进度（offset/head/tail）。
- `ISOLATE_SPM`：stage 间通过 send/fetch 传输，不共享页。
- `SHARED_SPM`：前后 stage 共享同一组页。
- `ALL_RINGBUFFER`：全部走 ring buffer，不额外预留普通 pipebuffer 容量。
- 类型定义：`tmp/MudnacSim/src/runtime/mapping.h:65`

### 6.3 ring buffer 回收语义

- `fill(offset)`：tail++，并初始化 `use_count[offset]=out_degree`。
- `use(offset)`：消费后 `use_count--`，当减到 0 且位于 head 时推进 head。
- 代码：
  - `tmp/MudnacSim/src/runtime/pipeline_buffer.cpp:65`
  - `tmp/MudnacSim/src/runtime/pipeline_buffer.cpp:52`

## 7. SPAD(SPM) 管理机制

### 7.1 总体调用路径

- 资源申请入口：`GenerateAction`
  - 先 `AllocAcc` 再 `AllocSpm`
  - `tmp/MudnacSim/src/runtime/runtime.cpp:815`
- 释放入口：`ReleaseAction`，统一回收 weight/in_stage/ringbuffer 页。

### 7.2 `ALL_BANK_PAGE_INTER`

- 核心入口：`AllocSpmAllBankPageInter`
  - 一次性从全 bank 交错取页。
  - 依次切分给 weight、in-stage（含单双缓冲）、shared、ringbuffer。
  - `tmp/MudnacSim/src/runtime/runtime.cpp:962`

### 7.3 `MIN_DIS`

- 核心入口：`AllocSpmMinDis`
  - 先按“相关 stage 的 acc 集”作为 preferred bank 分配。
  - 不足时按曼哈顿距离逐层扩展 bank 组。
  - `tmp/MudnacSim/src/runtime/runtime.cpp:1111`

### 7.4 SPM 物理页管理器

- 页粒度分配器：`SPMManager` 支持指定 bank / 全 bank 交错分配。
- 代码：`tmp/MudnacSim/src/runtime/spm_manager.cpp:1`

## 8. 多模型调度机制（QoS）

### 8.1 profiling 载入与查询

- `PipelineProfilingResult::loadFromFile` 读取 `schedule_point_profiling_<method>.yaml`。
- 构建 `PreprocessedEntry`：`cost`、`mapping_paths`、`pre_cost`、`remain_cost`。
- 代码：`tmp/MudnacSim/src/runtime/runtime.cpp:2072`

### 8.2 线程调度状态机

- `ThreadQoSPipeline::tick`：
  - `FETCH_NEXT_TASK -> WAIT_UNTIL_DISPATCHED -> RESOURCE_ALLOC/WAIT -> CREATE_PIPELINE_THREAD -> RUN`
  - `tmp/MudnacSim/src/runtime/thread_qos_pipeline.cpp:55`
- 资源调参：根据 deadline slack 与 `remain_cost`，动态增加/减少 acc target。

### 8.3 subgraph 执行选择

- 在 `CREATE_PIPELINE_THREAD` 状态按当前 target 读取：
  - `profiling_entry.mapping_paths[subgraph_idx]`
- 再用该路径加载 `PipelineMapping` 并执行当前 subgraph。

## 11. 已知风险与实现现状

1. CMake 源文件引用不一致
- `tmp/MudnacSim/CMakeLists.txt` 引用了仓库中缺失的 `qos_scheduler_new.cpp`、`thread_qos_pipeline_new.cpp` 等，当前构建配置存在漂移风险。

2. Profiling target 的等价判定风险
- `PipelineProfilingResult::Target::operator==` 未比较 `model_idx`，但哈希包含 `model_idx`，可能产生 key 一致性问题：
  - `tmp/MudnacSim/src/runtime/runtime.cpp:2036`
  - `tmp/MudnacSim/src/runtime/runtime.cpp:2060`

3. 执行侧 target 组装硬编码
- `GenerateTarget` 内 `dram_bw` 固定为 `19`，当 profiling 包含其它 dram_bw 组合时存在匹配偏差风险：
  - `tmp/MudnacSim/src/runtime/runtime.cpp:943`

4. 调度点脚本参数语义偏移
- `create-pipeline-schedule-point.py` 中 `Target(numArrays=512, ...)` 与常规 ACC 候选集（8/16/24/32）不一致，建议后续核对是否为有意放宽。

5. 现状说明
- 尽管存在上述风险，当前仓库中“产物格式 -> runtime parser -> pipeline 执行”的主链路是连通的，且路径契约通过符号链接统一。
